# New public source integration — development measurement

This directory measures catalog coverage using the unchanged production Rust ranker. It is not an agent evaluation or a final-set certificate. Do not use sealed data.

Inputs are read-only from `/Users/Marcin_1/Documents/Behavio.one/Projects/ui-component-finder/eval/`: `dev.json`, `score.mjs`, `PROTOCOL.md`, `README.md`, and the previously written `tuning/agent-queries.json`. Only its 120 English concise queries are used (105 answer, 15 reject). Existing explicit source constraints are identical in both arms. No query rewriting, threshold selection, new judgments, tuning, or live 21st requests are performed here.

1. `python3 probe.py` checks public index/license/item samples with at most four concurrent requests, bounded retries, logs and per-request checkpoints under ignored `evidence/`.
2. From the repository root, `GITHUB_TOKEN="$(gh auth token)" python3 experiments/new-sources/sync.py`. A fresh run creates a canonical temporary cache outside the repo. Resume reuses the cache in `sync.json`; `INTEGRATION_CACHE` can explicitly name that same canonical cache path. `sync.json` records every source's count, duration, failure and completion. Original sources are frozen into `baseline-index.json`; the final expanded cache into `expanded-index.json`.
3. Run `cargo run --locked --example new-sources-benchmark -- experiments/new-sources /Users/Marcin_1/Documents/Behavio.one/Projects/ui-component-finder/eval/tuning/agent-queries.json <canonical-cache>`. The existing Rust reader uses `GEMINI_API_KEY` or `CLAYUI_GEMINI_ENV_FILE`. The executed measurement mapped the already configured `GOOGLE_API_KEY` into the child process's `GEMINI_API_KEY`, without printing or persisting it. Empty both reader inputs for BM25 only. Document embeddings and query vectors use the existing model/dimensions/cache, with a saved checkpoint after every document batch and result after every query. API errors stop the run, rather than silently claiming Gemini results from a fallback.
4. `node experiments/new-sources/score.mjs /Users/Marcin_1/Documents/Behavio.one/Projects/ui-component-finder/eval` writes full conservative/optimistic scorer output, paired family-bootstrap differences (10,000, seed 20261109), input fingerprints and every unresolved top-five pair. The scorer requires unique IDs. Both catalog arms are normalized by full ID using the previous experiment's Map semantics (last value, first insertion position); the current Aceternity index repeats `background-lines` once. This normalization is only in the measurement harness.
5. `GITHUB_TOKEN="$(gh auth token)" python3 experiments/new-sources/smoke.py` checks source-scoped search/show/get into another canonical temporary directory. It never executes component code.

Large live index/code payloads and downloaded examples are intentionally excluded from git. Their SHA-256 fingerprints, final ranking lists, metrics, license texts, sync summaries and smoke evidence are committed. Live re-sync is a new catalog snapshot. Reproduce the exact measured snapshot using the cache path in `sync.json` and the indexed payloads preserved beside it; compare hashes before replay. Existing RareUI returned HTTP 404 in the baseline; both arms retain that failure.

See `REPORT.md` for the source-by-source scope, optional loader deferrals and limitations. Unknown pairs need two independent blind judges and separate arbitration before a relevance improvement can be established.
