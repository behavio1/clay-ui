# Kubai Icons as a Clay UI source

State: 2026-11-27. Branch `main`, base `96a35dd`. Local change for review: no commit, push, tag, npm publish or version bump.

**Verdict: admit with limits.** Kubai Icons enters as source `kubai-icons`: 1388 entries, one per icon object, with its styles and badged versions folded in. Only the MIT paths are read. The source is **left out of the default search** and answers only `search --source kubai-icons`. ## Licence audit

Files read at HEAD: `LICENSING.md`, `LICENSE` (Kubai Icons License), `LICENSE-ICONS` (MIT, "Copyright (c) 2026 Kubai087 and the Kubai Icons contributors"), `LICENSE-SITE`. The npm tarballs `kubai-icons@0.16.0` and `kubai-icons-react@0.16.0` declare MIT and include the same MIT text. The GitHub API reports `NOASSERTION` because the root `LICENSE` is the custom skill licence.

**Paths allowed in Clay UI** (`MIT_DIRS` and `LICENSE_FILE` in `src/kubai.rs`): `icons/`, `badges/`, `icons-duotone/`, `icons-line/`, `packages/`, plus `LICENSE-ICONS` so the MIT notice travels with each download. Every other path is never fetched. If a downloaded file imports one, that import is listed in `skipped` and not followed. The integration test checks that no request for `src/engine.js` is ever made.

**Does the MIT code need the source-available engine?** No. Every import in `icons/`, `badges/` and `packages/` was listed over the pinned tarball. They point only to `../packages/core/src/kit.js`, local `./_*.js` shape modules, `./*.js` inside `packages/core/src`, and the packages `react`, `vue` and `kubai-icons`. Nothing imports `src/`, `styles/`, `scripts/` or `tools/`. `kubai-icons-react/src/create.js` imports `kubai-icons/runtime`, which is `packages/core/src/runtime.js` (MIT). Section 3 of the skill licence covers icons a user draws with the skill and copies of `src/engine.js`. It does not apply to the MIT library, which runs on its own runtime. Not a blocking finding.

Notes that do not block admission:

- `packages/core/src/line-motion.js` shares 197 of its 201 non-trivial lines with `styles/line/motion.mjs` (source-available); its header says it is the same engine. `render.js`, `kit.js` and `runtime.js` share only 13/299, 33/156 and 2/87 lines with `src/engine.js`. The copyright holder publishes the `packages/` copy under MIT, and Clay UI downloads only that copy.
- The MIT files have no per-file copyright header, and `packages/*/LICENSE` is gitignored. `get` therefore adds the root `LICENSE-ICONS` to every download.
- The Kubai and Lumno names and logos fall under none of the licences.
- Line-style names follow Lucide, Hugeicons and SF Symbols naming (per `styles/line/CHANGELOG.md`), and some tags are SF Symbols identifiers. A geometry spot check against Lucide (`a-arrow-down`, `airplay`, `alarm-clock-check`) found different paths, so the drawings are not copied. That is three samples, not a full audit.

## Risks

- **Two upstream channels.** The catalog follows npm `latest`, code follows the git tag; without tags, `get` falls back to the default branch, which can be ahead of the package.
- **jsDelivr** is a new host; if it fails, sync fails this source and keeps its last good data.
- **Fast-moving upstream.** Names can change; a renamed icon gives a warning and exit 3 on `get` until the next sync.
- **Thin text for line-only objects.** 179 entries have no tag beyond their category; keyword search finds them by name only, and Gemini is untested here.
- **Discovery depends on the skill.** Icons need `--source kubai-icons`; the skill now says so.
- **Licence drift.** The MIT scope is fixed in code by path; if LICENSING.md moves paths, the guard must be updated by hand. The npm licence check covers only the package.
